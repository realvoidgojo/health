# Admin Contribution Guide

## Overview

I worked on the admin operations module of the Health Insurance Management System. My contribution focused on giving the administrator a single dashboard to manage claims, policies, user reactivation requests, and system reports.

The admin flow starts after login in [main.py](/home/rvg/health/main.py) and is implemented mainly through the controller, service, and repository layers in the `app/` package.

## What I Implemented

### 1. Admin Dashboard

I created the admin dashboard menu so an administrator can move between major operations from one place.

The dashboard flow is implemented in [app/controllers/admin_controller.py](/home/rvg/health/app/controllers/admin_controller.py), and role-based routing happens after login in [main.py](/home/rvg/health/main.py).

### 2. Claim Assignment

I implemented the claim assignment flow so unassigned claims can be allocated to claim officers.

Flow:

Admin Dashboard -> Claim Management -> View Unassigned Claims -> Select Claim -> Select Claim Officer -> Validate -> Update claim status to UNDER_REVIEW -> Write claim history entry

This logic is split across:

- [app/controllers/admin_controller.py](/home/rvg/health/app/controllers/admin_controller.py)
- [app/services/admin_service.py](/home/rvg/health/app/services/admin_service.py)
- [app/repositories/claim_repository.py](/home/rvg/health/app/repositories/claim_repository.py)

The system validates that the officer is active and has the correct role before assignment. It also records the action in claim history, which acts as the audit trail for claim operations.

### 3. View All Policies and Search

I implemented the admin policy view so the administrator can list all customer policies and search by policy ID.

Flow:

Admin Dashboard -> Policy Management -> View All Customer Policies or Search Customer Policy by ID

This is handled by:

This is handled by:

### 6. Reports and Audit Logs

I added system reporting so the administrator can view active policies, expired policies, approved claims, rejected claims, and agent performance.

Reports are generated in:

- [app/controllers/admin_controller.py](/home/rvg/health/app/controllers/admin_controller.py)
- [app/services/admin_service.py](/home/rvg/health/app/services/admin_service.py)
- [app/repositories/report_repository.py](/home/rvg/health/app/repositories/report_repository.py)

- [app/repositories/claim_repository.py](/home/rvg/health/app/repositories/claim_repository.py)
- [app/services/officer_service.py](/home/rvg/health/app/services/officer_service.py)

That means claim assignment and officer actions can be traced later through history records.

## End-to-End Flow

Admin login -> role check -> admin dashboard -> selected admin action -> service validation -> repository update -> console feedback

This layered structure keeps the code clean:

- Controller handles menu and input
- Service handles business rules and validation
- Repository handles database queries
- Views handle console output

## Validation and Security

I used service-layer validation to protect the admin operations. The code checks:

- Correct roles before assignment
- Active or inactive user status
- Claim status before reassignment
- Valid input formats for email, phone, date, and password

Security-related checks and exception handling are centralized in the service layer, which reduces the risk of invalid state changes.

## Example Methods

### Claim assignment service

```python
@staticmethod
def assign_claim(admin_id: int, claim_id: int, officer_id: int):
    officer = UserRepository.get_by_id(officer_id)
    if not officer or officer['role'] != Role.CLAIM_OFFICER or not officer['is_active']:
        raise ValidationError("Valid and active Claim Officer ID is required.")

    claim = ClaimRepository.get_claim_by_id(claim_id)
    if not claim or claim['status'] != ClaimStatus.PENDING_ASSIGNMENT:
        raise BusinessRuleError("Claim is not pending assignment.")

    ClaimRepository.assign_claim(claim_id, officer_id)
    ClaimRepository.add_claim_history(
        claim_id,
        admin_id,
        ClaimAction.ASSIGNED,
        f"Assigned to officer {officer_id}"
    )
```

### Reactivation approval service

```python
@staticmethod
def process_reactivation(admin_id: int, request_id: int, user_id: int, action: str, remarks: str = None):
    if action == "APPROVE":
        ReactivationRepository.update_request_status(
            request_id,
            ReactivationStatus.APPROVED,
            remarks
        )
        UserRepository.reactivate(user_id)
    elif action == "REJECT":
        ReactivationRepository.update_request_status(
            request_id,
            ReactivationStatus.REJECTED,
            remarks
        )
    else:
        raise ValidationError("Invalid action.")
```
